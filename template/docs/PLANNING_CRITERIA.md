# 企画審査基準

不合格の例は、筆者のAI会社の最初の案件（スキルマーケットでの小さな作業代行）で実際に起きたこと。
企画を「採用」するには、下の G1〜G8 をすべて満たすこと。1つでも [推測] だけの項目が残る案は採用しない。満たす案が無ければ、Rootは全案を却下する。

## 審査項目
| # | 問い | 合格の証拠 | 不合格の例（実例） |
|---|---|---|---|
| G1 | **誰が、何に困って、どこで、何にお金を払っているか**を一文で書けるか | 実在の依頼文・質問・レビューの原文3件以上から特定し、URL付きで引用 | 「個人・小規模の人」 |
| G2 | **無料の代替（AI・無料記事・公式ヘルプ）ではなく払う理由**が、顧客自身の言葉で残っているか | 「AIで試したが…」「自分では無理だった」等の原文 | 「本人の表への当てはめで詰まる。差は中〜大」と自社が推測 |
| G3 | **自社と同じ条件の売り手（実績0、無名）が売れているか** | 実績0〜数件の出品・商品で、直近に販売がある例を複数確認 | 実績の多い上位の出品者を根拠にした。同条件の出品は0件のままだった |
| G4 | **既存の競合ではなく当社を選ぶ理由**が、顧客から見て確認できるか | 競合が満たしていない要求を、レビューの不満や未回答の依頼で示す | 安さと「検証します」という作り手側の工程 |
| G5 | **反証を先に探したか** | 売れていない同種商品を調べ、その共通点と、自社がそれに当てはまらない理由を記録 | 売れている例だけを引用。不利な観測を「補助経路」と言い換えた |
| G6 | **初売上までの距離**を、範囲・根拠・不確実性・最悪の場合で示したか | 「最悪：○日で0件。根拠○」まで書く。成功談と失敗談を全案で同じ扱い | 推奨案だけ成功体験談（数日〜25日）、他案は失敗体験談 |
| G7 | **作る前に需要を確かめる工程**があるか | 制作前に、低コストで反応を測る方法と合格ライン（例：問い合わせ○件） | 需要が分かるのは公開後（T0+14日）。先に作り込みと品質で4回反復 |
| G8 | **独立した反対意見**が書面にあり、食い違いが整理されているか | 推奨者とは別の担当が「出すべきでない理由」を書き、Rootが採否理由を記録 | 販路調査（その販路は不利）と企画（その販路を推奨）の食い違いを放置 |

補足：
- 「出品・出版できるか」（規約・操作）と「出すべきか」（売れるか）は別の問い。前者の調査結果で後者を答えない。
- 価格×件数：手取りと、CLAUDE.md の目標金額まで必要な件数を書き、その件数が根拠のある範囲かを確かめる。
- 制作の作り込みや品質の反復は、G1〜G8 に合格した後にだけ行う。

## 進め方
1. **問題探索（マーケティング部）**：商品案ではなく、「お金を払って解決されている問題」を、支払いの証拠（実在の依頼・購入レビュー・有料相談の質問文）から集める。G1・G2 の材料。
2. **企画（企画部）**：問題ごとに、自社が提供できる最小の解決策と、G3〜G7 の評価。推奨の前に、推奨案を止める根拠を3つ以上探して同じ分量で書く。
3. **反証（別セッションの担当）**：推奨案を作っていない担当が、G1〜G8 の観点で「出すべきでない理由」を書く。企画の結論を読む前に、まず自分で証拠を当たる。
4. **Root審査**：G1〜G8 の表で判定。各部の結論を統合する前に、食い違いと [推測] の欄を一覧にする。全案却下も可。
5. **作る前の需要確認（G7）**：合格した案だけ、最小コストで反応を測る。合格ラインを越えたら制作へ。

## 小規模な市場検証の枠
上の G1〜G8 は、大きな投資をする企画の基準として残す。次の条件をすべて満たす小さな商品は、G1〜G8 を全部そろえなくても、最低限の品質と安全性を確保したうえで市場に出して検証する。
- 追加の費用が0円。
- Ownerの作業は、承認を除いて合計1時間以内。
- 撤回できる（出品の停止・非公開・返金で元に戻せる）。
- 法令違反、利用規約違反、個人情報の漏えい、データ破損のリスクがない（ここは品質管理の重大差止めの対象のまま）。
- **検証する価値がある**：買い手がその販路で実際に探している、または依頼を出している証拠が1件以上ある。

「競合がいる」「無料の代替がある」「売れるか分からない」だけでは、却下の理由にしない。却下できるのは「検証する価値がない」場合（買い手が来る経路が一つも示せない、学べることがない）だけ。
G6（初売上までの距離）と撤退条件は、この枠でも必ず書く。
